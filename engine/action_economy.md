# 行动经济系统

## 核心原则

选择的意义不在于系统只允许点击一个字母，而在于玩家无法同时获得所有选择的完整收益。

系统不禁止玩家合并行动，但必须让行动争夺有限资源。当资源充足时，组合是合理的；当资源紧张时，取舍自然产生。

## 一、行动分类

### 短行动（Minor Action）

可以组合、排序、批量安排。通常不单独构成决策点。

示例：找人简短谈话、查看面板、检查装备、短距离移动、问一个问题、整理背包。

特征：
- 时间成本 ≤ 30分钟
- 体力/精神成本极低
- 不占用"主要行动槽"
- 不触发独占事件窗口

### 重大承诺（Major Commitment）

必须争夺时间、资源、风险或立场。通常不能全部完成。

示例：花整晚加固索具、深度脉感探索、陪伴NPC度过关键夜晚、跟随拾荒队执行限时任务、完整休息恢复状态。

特征：
- 时间成本 ≥ 60分钟
- 消耗显著体力/精神/物资
- 占用"主要行动槽"
- 可能触发独占事件窗口
- 做了A就意味着这轮做不了B（或只能低质量完成B）

## 二、时段与行动槽

每个时段（清晨/白天/黄昏/夜晚）提供：

```
行动槽 = 1个主要行动 + 2个短行动
```

特殊情况修正：
- 疲劳状态（体力<30）：短行动槽 -1
- 受伤状态：主要行动效率 ×0.7
- 紧急事件（灾难/战斗）：取消短行动槽，全部精力用于应对
- 安全基地内且无威胁：短行动槽 +1（ 여유时间）

GM在描写时段转换时，应明确告知玩家当前可用行动容量：

```
距离天黑还有两个小时。你最多能完成：
- 两项短行动；或
- 一项需要专注的完整行动。
```

## 三、行动成本结构

每个可执行行动必须有明确成本：

```yaml
action:
  name: ""
  type: minor / major
  cost:
    time_minutes: 0        # 所需时间
    stamina: 0             # 体力消耗
    mental: 0              # 精神消耗
    resources: {}          # 物资消耗
    risk: 0                # 风险暴露(0-100)
  requirements:
    location: ""           # 需要在哪里
    npc_available: ""      # 需要哪个NPC在场
    items: []              # 需要什么物品
    knowledge: ""          # 需要什么前置知识
  tags: []                 # LLM意图标签，不参与硬约束
```

行动计划的硬约束由世界注册表提供，典型结构为：

```yaml
constraints:
  system_tags: [major_action, requires_full_attention]
  exclusive_group: evening_major_action
  window_id: day3_evening
  window_capacity: 1
  commitment_axis: faction_loyalty
  commitment_value: black_tower
```

同一 `commitment_axis` 重复同一 `commitment_value` 不冲突；同一轴出现不同值才冲突。
机会窗口只在同一 `exclusive_group`、同一 `window_id` 超过 `window_capacity` 时冲突；
不同窗口可以按顺序完成。LLM 的 `tags` 不得替代这些结构化字段。

### 成本参考表

| 行动类型 | 时间 | 体力 | 精神 | 备注 |
|----------|------|------|------|------|
| 简短对话(5-10句) | 15-30min | 1-2 | 2-4 | 短行动 |
| 深度社交事件 | 60-120min | 3-5 | 8-15 | 主要行动 |
| 普通感知/侦查 | 30-45min | 3-5 | 10-15 | 短行动(上限) |
| 深度感知/研究 | 120-180min | 5-8 | 25-40 | 主要行动，可能反噬 |
| 体力劳动(加固/搬运) | 120-240min | 20-35 | 3-5 | 主要行动 |
| 战斗(遭遇战) | 10-30min | 10-25 | 5-15 | 强制中断当前行动 |
| 完整休息 | 360-480min | 恢复 | 恢复 | 占用整个时段 |
| 制作/锻造 | 60-180min | 8-15 | 5-10 | 需要工具和材料 |
| 探索(新区域) | 120-240min | 15-25 | 10-20 | 主要行动 |
| 移动/进入地点 | 由地点注册表决定 | 由地点注册表决定 | 由地点注册表决定 | 必须使用 `TRAVEL` / `ENTER_LOCATION` |
| 返回基地/撤离 | 由地点注册表决定 | 由地点注册表决定 | 由地点注册表决定 | `RETURN_TO_BASE` / `EXTRACT` |
| 属性点分配 | 0 | 0 | 0 | `ATTRIBUTE_ALLOCATION`；只消耗已有自由属性点 |
| 等待 | 5-720min(自定义) | 0 | 0 | `WAIT`；只推进时间，用于计划中等待合法时段窗口 |

## 四、专注稀释（Dilution）

当玩家在一个时段内尝试组合多个行动时，不机械拒绝，而是计算稀释效果。

### 专注度公式

```
行动有效度 = 基础能力 × 投入时间比例 × 专注修正 × 状态修正
```

专注修正：
- 单一主要行动：×1.0（完全专注）
- 两个行动分享时段：各 ×0.75
- 三个行动分享时段：各 ×0.55
- 四个及以上：各 ×0.4（几乎无法有效完成）

### 稀释后果

有效度降低意味着：
- 成功率下降（战斗/制作/感知）
- 获得信息不完整（只得到部分线索）
- 社交效果打折（NPC感到你心不在焉）
- 制作/加固质量降低（需要返工）
- 无法触发"完美完成"的额外奖励

### 结算示例

```
玩家：先找铆钉谈话，再做普通脉感，然后研究堡垒方案。

系统计算：
- 找铆钉(30min) + 普通脉感(40min) + 堡垒研究(≥180min) = 250min
- 剩余可用时间：240min
- 结论：前两项可完成，第三项只能做初步推演

系统回应：
"前两件事可以完成。但关于堡垒方案，你今晚只能形成初步假设，
无法完成实地调查或工程设计。若继续研究，你将没有时间休息。"
```

## 五、机会窗口（Opportunity Window）

某些行动有明确的时间边界，错过即消失或以不同形式重现。

### 窗口结构

```yaml
opportunity:
  id: ""
  description: ""
  available_from: "day_X_HH:MM"
  expires_at: "day_X_HH:MM"
  type: social / exploration / combat / economic / story
  competing_with: []          # 与之互斥的其他窗口ID
  consequence_if_missed: ""   # 错过后的后果
  recurrence: never / delayed / altered  # 是否重现
```

### 窗口设计原则

- 不是所有事件都有窗口。日常行动（吃饭、检查装备）永远可用。
- 窗口应提前预兆，不能突然消失。至少提前1-2轮暗示。
- 错过窗口的后果应该是"不同"而非"惩罚"。阿苔今晚不在，不代表永远不能发展关系，但情绪窗口关闭后，下次需要更多铺垫。
- 灾难/战斗是强制窗口，优先级最高，会中断其他行动。

### 窗口类型示例

| 类型 | 示例 | 过期后果 |
|------|------|----------|
| 社交情绪窗口 | NPC因恐惧/悲伤需要陪伴 | 关系推进需要更多时间 |
| NPC可用窗口 | 铆钉黄昏后带队外出 | 直到下次回来才能找 |
| 环境窗口 | 蜕震蓄力期才能深度脉感 | 等下次蜕震周期 |
| 工程截止 | 外围辅索必须今晚加 | 蜕震时外围无保护 |
| 经济窗口 | 铁片只接受最后一批定制 | 需要找其他途径 |
| 情报窗口 | 某人愿意透露秘密（仅限此刻） | 对方改变主意 |

## 六、NPC日程系统

NPC不是主题公园里永远站在原地的任务NPC。每个重要NPC有日程表。

### 日程结构（在npcs.yaml中）

```yaml
npc:
  id: ""
  name: ""
  schedule:
    dawn: ""          # 清晨在哪/做什么
    day: ""           # 白天
    dusk: ""          # 黄昏
    night: ""         # 夜晚
  exceptions: []      # 特殊日程（灾难日、任务日等）
  availability_notes: ""  # 额外说明
```

### 日程规则

- 玩家找NPC时，GM必须检查当前时段NPC是否在该位置。
- 如果NPC不在，告知玩家NPC去了哪里、什么时候回来。
- NPC日程可以因事件改变（灾难时所有人进入应急状态）。
- 不需要每轮都展示所有NPC日程，但玩家询问时应能回答。
- NPC日程之间的冲突自然产生选择张力：铆钉黄昏后外出，阿苔黄昏时在照顾妹妹——你黄昏只有一个时段。

## 七、互斥与冲突标签

### 承诺标签（Commitment Tags）

标记行动的资源占用类型：

```
evening_major_action      # 占用晚间主要行动槽
requires_full_attention   # 需要完全专注，不能分心
physically_exhausting     # 高体力消耗
mentally_draining         # 高精神消耗
location_locked           # 锁定在某地点，无法离开
socially_committed        # 社交承诺，中途离开会损害关系
```

### 冲突判定

当玩家尝试组合行动时，检查：

1. 时间冲突：总时间 > 可用时间？
2. 行动槽冲突：主要行动超过每时段 1 个，或短行动超过 2 个？
3. 地点/移动冲突：两个行动需要在不同地点，且移动窗口不足？
4. 专注冲突：高精神负荷行动与 `requires_full_attention` 同时发生？
5. 承诺轴冲突：同一 `commitment_axis` 是否出现不同 `commitment_value`？
6. 机会窗口冲突：同一 `exclusive_group` 的 `window_id` 是否超过容量？不同窗口默认可以顺序完成。
7. NPC冲突：两个行动需要同一个NPC同时配合不同事，或NPC日程显示不可用？
8. 资源冲突：两个行动消耗同一份稀缺物资？

任一冲突成立 → 不能同时完成 → 告知玩家必须取舍或接受稀释。

## 八、可组合度公式

当玩家提出组合行动时，系统计算可组合度：

```
Combinability =
  时间可行性
  × 资源兼容度
  × 地点接近度
  × 目标兼容度
  × NPC可用度
  × 专注兼容度
  × 行动槽兼容度
  × 承诺轴兼容度
  × 机会窗口兼容度
  × 移动兼容度
  × 100
```

| 可组合度 | 系统处理 |
|----------|----------|
| 80+ | 允许顺序完成，不必伪装成互斥选择 |
| 50-79 | 允许组合，但质量或休息受损（稀释生效） |
| 20-49 | 只能完成部分，要求玩家排序优先级 |
| <20 | 明确互斥，必须放弃其一 |

### 关键规则

如果可组合度 ≥ 80，系统从一开始就不应该把这些行动包装成"四选一"。正确写法是：

```
黄昏前，你还有时间完成两个短行动，或者一个完整的大行动。

短行动：
1. 找铆钉谈话（~30min）
2. 找阿苔告知笔记的事（~20min）
3. 做一次普通脉感（~40min）

完整行动：
4. 与焦叔加固外围索具（~3h）
5. 深度脉感研究排异问题（~2.5h）
6. 自由安排
```

## 九、知识获取限制

玩家提出问题 ≠ 主角获得答案。

### 规则

- 玩家问"能不能做X"时，GM只能基于主角当前知识回答。
- 主角没有足够知识时，只能给出假设，不能确认真相。
- 高级战略情报必须通过调查、实验、NPC交流逐步获得。
- 区分"主角的推测"和"世界的事实"。

### 正确示例

```
你目前只能判断：单纯把锚桩做得更粗更硬，未必能解决问题。
渊驮的身体似乎在主动排斥它。

但这是免疫排异、周期生长，还是某种更复杂的机制，你没有足够证据。
要得到答案，可能需要：检查旧桩残骸 / 研究蓝的笔记 / 前往北面寻找第二根锚桩。

【新假设】（未确认）
· 静态加固可能无法永久解决排异
· 锚桩破坏可能与渊驮生理反应有关

【待验证】
· 是否存在生物兼容材料
· 旧人的锚桩是否真正稳定
· 北面第二根桩是否仍存在
```

### 错误示例（禁止）

```
【战略认知】堡垒思路不可行。真正解法＝不被当作异物。答案在北面。
```

后者把假设直接变成了真理，剥夺了探索过程。

## 十、选项设计：从"行动"升级为"方案"

### 原则

选项不应是单个动作（找某人、去某地、做一次感知），而应是完整的战略方案。方案内部可以包含多个小动作，但整体争夺同一种有限资源。

### 方案结构

```
方案名：[一句话概括战略方向]
包含行动：[2-4个具体步骤]
预期收益：[获得什么]
预期代价：[失去什么/承担什么风险]
机会成本：[因此无法做什么]
```

### 六种冲突维度

好的方案之间应争夺至少一种共同资源：

1. **时间冲突**：今晚只够做一件大事
2. **立场冲突**：信息和所有权安排互相矛盾（上交/私分/独占）
3. **资源冲突**：同一份稀缺物资只能用于一处
4. **信任冲突**：对不同NPC说不同的话，无法同时维持
5. **风险冲突**：安全位置只有一个，去了A就顾不上B
6. **价值观冲突**：保护集体/保护亲近的人/提升自己/夺取权力

### 方案展示格式

```
你准备怎么做？

A. [方案名]
   [2-3句描述具体做什么]
   → 预期：[收益] / [代价]

B. [方案名]
   [2-3句描述]
   → 预期：[收益] / [代价]

C. [方案名]
   ...

D. 自由行动（描述你想做什么，系统会拆解结算）
```

注意：不在选项中剧透具体数值结果，但应暗示方向性代价。

## 十一、自由输入拆解结算

当玩家输入组合行动时，GM必须：

1. 拆解为独立行动列表
2. 逐项计算成本
3. 检查总成本 vs 可用资源
4. 判定可组合度
5. 告知玩家哪些能完成、哪些只能部分完成、哪些必须放弃
6. 玩家确认后，逐项结算

### 结算流程

```
玩家输入："先找铆钉，然后脉感，再研究堡垒"
    ↓
拆解：[社交30min] + [感知40min] + [研究180min] = 250min
    ↓
可用时间：240min
    ↓
可组合度计算：时间不足 → 65分
    ↓
系统回应：
"前两项可以完成。堡垒研究只能做初步推演（约60min），
无法完成实地调查。若坚持深入研究，你将完全没有休息时间。"
    ↓
玩家选择：
- 接受初步研究
- 放弃脉感，深入研究
- 全部尝试（接受疲劳后果）
- 重新安排
    ↓
逐项结算，更新状态
```

### 强行全部的代价

如果玩家坚持超出容量的组合：
- 每项行动有效度 ×0.5-0.6
- 体力/精神额外消耗 ×1.5
- 下一时段行动槽 -1（疲劳累积）
- 可能触发"失误"事件（制作失败、说错话、感知偏差）
- 不禁止，但后果真实

## 十二、选项合法性前置

### 核心规则

合法性审核必须发生在展示之前，而不是玩家选择之后。

`compile_options()` 对每个候选行动调用 `preview_host_action()`。只有 `preview.legal == True` 的候选才能进入最终选项列表。时段（`allowed_periods`）、地点、物品、等级、NPC可用性等所有前置校验都在展示之前完成。

### 正确流程

```text
生成候选"开始探索废铁站场"
  → 模拟当前状态
  → 检查当前位置：废铁站场，通过
  → 检查当前时段：清晨，不通过（允许：白天、黄昏）
  → 从候选列表删除
  → 玩家永远看不到这个选项
```

### 错误流程（禁止）

```text
生成候选"开始探索废铁站场"
  → 直接展示给玩家
  → 玩家选择
  → 结算时才发现时段不合法
  → 拒绝执行
```

这不是有意义的失败或游戏风险，而是选项生成顺序错误。

### 时段受限时的替代方案

当目标行动因时段不合法被丢弃时，主持器应提供合理的替代选项：

- 在当前地点执行不受时段限制的短行动（观察、整理、交谈）
- 返回基地准备装备或休息
- 提交含 `WAIT` 步骤的 ACTION_PLAN，等待进入合法时段后再执行
- 自由行动

### WAIT 行动与计划内时段模拟

`WAIT` 只推进时间（5-720分钟），不消耗体力/精神，不触发随机事件。在 ACTION_PLAN 中，Python 按步骤顺序模拟执行，每一步使用模拟后的 `time_of_day` 进行合法性检查。因此"等待120分钟 → 探索废铁站场"的计划会在等待推进到白天后，正确通过探索的时段检查。

### 选项过期

选项绑定 `state_turn`。任何玩家行动提交后，旧选项自动清除。`preview_player_choice()` 在选择时重新校验存储的契约；时段或状态变化后不再合法的选项会被拒绝执行。
