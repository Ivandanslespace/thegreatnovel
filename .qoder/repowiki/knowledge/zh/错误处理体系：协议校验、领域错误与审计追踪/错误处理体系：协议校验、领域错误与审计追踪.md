## 1. 系统/方法概述
该仓库采用「协议层严格校验 + 领域层结构化错误列表 + 审计日志可追溯」的分层错误处理策略。LLM 主机通过 JSON 协议提交意图，Python 引擎在 protocol.py 中做白名单校验并抛出 ProtocolError；GameEngine 内部用 list[str] 返回业务规则错误（如时间不足、资源不足、地点不符等）；所有执行路径均通过 audit.py 生成决策审计记录，形成完整可复盘的错误链。

## 2. 关键文件与包
- engine_runtime/protocol.py：定义 ProtocolError、ALLOWED_ACTION_FIELDS、ENGINE_ONLY_FIELDS、ACTION_PROFILES，validate_host_action() 对 LLM 输入做字段白名单与嵌套结构校验。
- engine_runtime/runtime.py：GameEngine 核心类，集中实现 _check_requirements()、_target_presence_errors()、_derived_budget_errors() 等返回 list[str] 的业务校验函数，并在非法状态时 raise ValueError。
- engine_runtime/calculators.py：确定性计算器，check_skill_use()、calculate_build() 等返回 errors 列表而非抛异常，用于非致命性约束检查。
- engine_runtime/audit.py：build_execution_audit() / build_rejected_audit() 生成标准审计 JSONL，append_audit_record() 强制去重（重复 audit_id 抛 ValueError）。
- tools/turn_controller.py & tools/game_turn.py：两阶段 CLI 入口，resolve 阶段捕获 ValueError/JSONDecodeError 并返回结构化 error 字段，record 阶段校验 GM 文本禁止词与选项标签一致性。
- tools/validate_save.py：存档六类校验器（连续性/规则/知识/战力/关系/叙事），collect_findings() 按 CRITICAL/ERROR/WARNING/INFO 分级，assert_startable() 作为启动门禁。

## 3. 架构与约定
- 协议边界（LLM ↔ Python）：validate_host_action() 拒绝未知字段、禁止引擎内部字段（ENGINE_ONLY_FIELDS）、校验 ACTION_PLAN.steps 类型白名单，失败统一抛 ProtocolError(ValueError)。
- 领域规则（GameEngine）：不抛异常而是收集 list[str] 错误（如“时间不足”“体力不足”“精神不足”“目标未注册”“当前时段不可执行”），由调用方决定是返回预览还是拒绝执行。
- 计算模块（calculators.py）：对可恢复的约束（技能冷却、材料不足、基地空间不足、建造时间不足）返回 errors 列表，success 标志位由 caller 判断。
- 审计追踪：每次成功执行生成 EXECUTED 审计，被拒绝则生成 REJECTED 审计，包含 player_input、llm.intent、python.validation.stage、decision_chain、state_diff 等字段，写入 decision_audit.jsonl 与 decision_audit.md。
- 存档门禁：validate_save.assert_startable() 在 turn_controller/game_turn 启动时调用，CRITICAL/ERROR 直接 raise ValueError 阻止进入游戏流程。

## 4. 约定与约束
- LLM 不得提交 ENGINE_ONLY_FIELDS 中的任何字段，否则 validate_host_action() 会列出具体路径并抛 ProtocolError。
- ACTION_PLAN 的 steps[].type 必须属于 ACTION_PROFILES 减去 {"ACTION_PLAN"}，否则报“不是有效行动类型”。
- ATTRIBUTE_ALLOCATION 必须在 parameters.allocations 提交属性分配，且每个属性只能分配一次正整数点数。
- GameEngine._check_requirements() 强制要求：回合结束/角色死亡后仅允许 ENDING/RESTART/CHECKPOINT/LEGACY_CREATE；pending_decision 未解决时不允许非 TALENT_CHOICE 行动。
- 移动/撤离类行动必须由 Python 路线成功结果驱动，runtime.py 第 640 行明确 raise ValueError("移动/撤离没有获得 Python 路线成功结果，拒绝修改地点状态")。
- 审计记录 audit_id 全局唯一，append_audit_record() 检测到重复即抛 ValueError("审计记录已存在：...")。
- record 阶段 GM 回答禁止包含 FORBIDDEN_TERMS（"预览合法"、"未结算"、"Python"、"SQLite"、"dry-run"、"action_id"、"确认执行"、"compile_options"、"preview"），且必须展示所有 pending_options 的 label。
- 存档校验器将问题分为 CRITICAL/ERROR/WARNING/INFO 四级，assert_startable() 阻断 CRITICAL/ERROR 继续运行。
- 事件溯源要求 Turn 17 起的标准事件必须携带 event_id、action_ledger（含 available_time_minutes/stamina_cost/mental_cost/actions），缺失则记为 ERROR。

## 5. 错误分类速览
| 层级 | 机制 | 典型来源 |
|---|---|---|
| 协议层 | ProtocolError(ValueError) | validate_host_action() 字段白名单、嵌套结构校验 |
| 领域层 | list[str] 错误列表 | _check_requirements()、_target_presence_errors()、check_skill_use()、calculate_build() |
| 运行时 | ValueError | 非法状态转换（移动/撤离无成功结果、重复审计ID、缺少必要参数） |
| 审计层 | REJECTED/EXECUTED 记录 | build_rejected_audit()/build_execution_audit() 区分失败与成功路径 |
| 存档门禁 | assert_startable() 抛 ValueError | validate_save 六类校验汇总 CRITICAL/ERROR 阻断启动 |

该体系确保 LLM 无法绕过 Python 规则、所有错误可追溯、存档完整性可验证，形成从输入到持久化的全链路错误治理。
